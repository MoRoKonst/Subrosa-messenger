## Обзор

Beacon — self-hosted зашифрованный мессенджер, разработанный для применения в условиях противодействия. В отличие от большинства мессенджеров, защищающих только содержимое сообщений, Beacon защищает также **граф социальных связей** — кто с кем общается — с помощью анонимной маршрутизации по токенам, cover traffic и поддержки Tor hidden service.

Сервер не имеет доступа к открытому тексту сообщений, личным данным пользователей, ключам или медиапотокам звонков. Все криптографические операции выполняются на клиенте.

**Минимальная версия Android:** 8.0 (API 26)  
**Target SDK:** 34  
**Языки:** Kotlin (Jetpack Compose), Python 3 (сервер)

## Функциональность

### Сообщения
- Зашифрованная переписка один-на-один
- Голосовые сообщения
- Передача изображений и файлов (чанкованная, до 6 МБ на пакет)
- Исчезающие сообщения с настраиваемым TTL
- Реакции, редактирование, удаление сообщений
- Ответы с цитированием
- Статусы прочтения и доставки
- Черновики сообщений

### Группы
- Зашифрованные групповые чаты
- Отдельный ключ AES-256 на группу, зашифрованный для каждого участника
- Роли администратора и участника
- Описание группы и эмодзи-аватар
- Ротация ключа при исключении участника

### Голосовые и видеозвонки
- Peer-to-peer аудио и видео через WebRTC
- TURN-ретрансляция по TCP (порт 4433) для обхода NAT
- Сигнализация через сервер — медиапоток не проходит через сервер

### Контакты и приглашения
- Инвайт-коды с ECDSA-подписью и TTL 7 дней
- Обмен через QR-код
- Экран верификации отпечатка ключа (защита от MITM вне системы)
- Аватар контакта (128×128 JPEG)

### Безопасность
- Полный Signal Protocol: X3DH + Double Ratchet v3 (DH Ratchet + Symmetric Ratchet)
- Прямая секретность и восстановление после компрометации на каждом обмене
- Двойное шифрование на устройстве: AndroidKeyStore + Storage Master Key (AES-256)
- Биометрическая разблокировка
- Пароль-паника (беззвучное уничтожение данных при попытке входа)
- Кнопка паники в уведомлении (вайп доступен с заблокированного экрана)
- Три уровня уничтожения данных: SOFT / HARD / NUCLEAR
- Режим-приманка (фиктивный аккаунт после уничтожения данных)
- Мёртвая рука (Dead Man's Switch) с настраиваемым интервалом
- Параноидный режим (подавление логов, HTTP-оповещение об угрозе)
- Обнаружение вторжения: прокси, пользовательский CA, VPN, ADB, режим разработчика
- Антиотладка
- Защита от скриншотов (`FLAG_SECURE`)
- Обнаружение root
- Привязка сертификата (certificate pinning)

### Резервное копирование
- Полный зашифрованный бэкап включая EC-ключевую пару (fingerprint сохраняется после вайпа и восстановления)
- AES-256-GCM + Argon2id (m=64 МБ, t=3) — устойчив к GPU-брутфорсу
- Экспорт в файл или через системный диалог

## Архитектура приватности

Большинство мессенджеров защищают содержимое сообщений, но не метаданные — сервер по-прежнему видит кто с кем общается, когда и как часто. Beacon закрывает этот вектор четырьмя независимыми слоями.

### 1. Анонимная маршрутизация по токенам

Сообщения адресуются не по fingerprint пользователя, а по одноразовым случайным токенам. Сервер хранит только маппинг `токен → WebSocket` без привязки к личности. После доставки токен удаляется.

```
Стандартно:  { "from": "A1B2C3D4", "to": "9F8E7D6C", "text": "<зашифровано>" }
Beacon:      { "type": "anon_message", "token": "e39f0134...", "payload": "<зашифровано>" }
```

Сервер видит анонимный блоб — не пару `from → to`.

### 2. Анонимный mailbox (первый контакт)

Первое сообщение обычно раскрывает пару `A → B`. Beacon решает это через анонимный mailbox, встроенный в каждый инвайт-код. Bob кладёт зашифрованный блоб в mailbox Alice; Alice запрашивает его вместе с 19 случайными фейковыми тегами — сервер не знает какой из них настоящий.

### 3. Cover Traffic

Даже без идентификаторов возможна timing-атака по корреляции трафика. В агрессивном режиме Beacon отправляет постоянный поток (1 пакет/сек); реальные сообщения занимают место шумовых пакетов. Наблюдатель видит равномерный поток вне зависимости от реального общения.

| Режим | Интервал | Трафик |
|---|---|---|
| Выключен | — | только реальные сообщения |
| Умеренный | 1 пакет / 5 сек | ~2–3 МБ/час |
| Агрессивный | 1 пакет / сек | ~20–30 МБ/час |

Шумовые пакеты структурно идентичны реальным — тот же тип, случайный токен, payload с паддингом до фиксированного размера.

### 4. Tor Hidden Service

Сервер поддерживает `.onion` адрес. Трафик идёт полностью внутри сети Tor — без exit-нод, без раскрытия IP, без Cloudflare в цепочке. Приложение использует Orbot и автоматически выбирает корректный режим прокси для `.onion` и clearnet адресов.

### Итоговая таблица угроз

| Наблюдатель | Без Beacon | С Beacon |
|---|---|---|
| Сервер / утёкшие логи | Граф `from → to`, содержимое | Анонимные блобы и токены — нет привязки к личности |
| Враждебный оператор сервера | Граф `from → to`, содержимое | Таблица токенов (решение — самохостинг) |
| ISP отправителя | IP сервера, время и объём | Зашифрованный Tor трафик |
| ISP получателя | IP сервера, время и объём | Зашифрованный Tor трафик |
| Оба ISP одновременно | Timing-корреляция | Статистически значительно сложнее (constant-rate) |
| Целевая операция (MITM, устройство) | Всё | Содержимое защищено E2EE |

## Системные требования

### Клиент
- Android 8.0+ (API 26)
- Google Play Services (опционально, для push-уведомлений)
- Orbot (опционально, для Tor hidden service)
- Разрешения на камеру и микрофон для звонков

### Сервер
- Python 3.10+
- Библиотеки: `websockets`, `cryptography`
- Доступный IP-адрес с открытым портом 443 (WSS через обратный прокси)
- TURN-сервер для обхода NAT (рекомендуется coturn)

## Развёртывание сервера

```bash
cd ForEXP
pip install websockets cryptography
python server.py --dev
```

### Настройка nginx (обратный прокси + TLS)

```nginx
location /ws {
    proxy_pass http://127.0.0.1:9000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 86400;
}
```

### Подключение приложения к своему серверу

Пересборка не требуется. В приложении:

1. Перейдите в **Профиль → Серверы**
2. Нажмите **+** для добавления сервера
3. Введите адрес и порт вашего сервера
4. Нажмите на сервер для переключения — приложение переподключится немедленно

### TURN-сервер (coturn)

Необходим для WebRTC-звонков через NAT:

```
listening-ip=<IP_СЕРВЕРА>
relay-ip=<IP_СЕРВЕРА>
listening-port=4433
lt-cred-mech
user=<ИМЯ>:<ПАРОЛЬ>
realm=beacon
```

## Сборка

### Требования
- Android Studio Hedgehog (2023.1) или новее
- JDK 17
- Android SDK с API 34

### Шаги

```bash
git clone https://github.com/MoRoKonst/beacon-messenger
cd beacon-messenger

# Отладочный APK
./gradlew assembleDebug

# Релизный APK (требует настройки подписи)
./gradlew assembleRelease
```

Релизный APK сохраняется в `app/build/outputs/apk/release/`.

### Настройка подписи

```kotlin
signingConfigs {
    create("release") {
        storeFile = file("your-keystore.jks")
        storePassword = System.getenv("KEYSTORE_PASSWORD")
        keyAlias = "messenger"
        keyPassword = System.getenv("KEY_PASSWORD")
    }
}
```

## Быстрый старт

1. Установите APK из [Releases](https://github.com/MoRoKonst/beacon-messenger/releases).
2. Откройте приложение, зарегистрируйте имя пользователя и пароль.
3. Поделитесь инвайт-кодом с контактом (`beacon://invite?...`).
4. Сверьте fingerprint контакта вне системы (рекомендуется).
5. Начните переписку.

**Для использования своего сервера:** см. [Развёртывание сервера](#развёртывание-сервера), затем добавьте сервер в **Профиль → Серверы**.

## Безопасность

| Уровень | Механизм |
|---|---|
| Транспорт | WSS (TLS 1.2+) с привязкой сертификата |
| Согласование ключей | X3DH (Identity Key + Signed Prekey + One-Time Prekey) |
| Сквозное шифрование | Double Ratchet v3 — DH Ratchet + Symmetric Ratchet, AES-256-GCM |
| Прямая секретность | Уникальный ключ на каждое сообщение; восстановление после компрометации на каждом DH-шаге |
| Граф социальных связей | Анонимная маршрутизация по токенам — сервер не видит пары `from → to` |
| Timing-атаки | Constant-rate cover traffic (опционально) |
| IP-адрес | Tor hidden service через Orbot (опционально) |
| Данные на устройстве (L1) | EncryptedSharedPreferences + AndroidKeyStore |
| Данные на устройстве (L2) | Storage Master Key, AES-256-GCM |
| Резервные копии | AES-256-GCM + Argon2id (m=64 МБ, t=3, p=1) |
| Аутентификация ключей | ECDSA (SHA256withECDSA) + верификация fingerprint вне системы |
| Защита от Invalid Curve Attack | Валидация EC-точки для всех импортируемых публичных ключей |

Подробности — в [SECURITY_RU.md](SECURITY_RU.md).
