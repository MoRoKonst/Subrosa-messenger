# Карта функций Subrosa Messenger — для проверки

Не техническая документация — просто список всего, что можно сделать в приложении, чтобы сесть и пройтись по каждому пункту. Android и Desktop указаны отдельно там, где есть разница.

---

## 1. Регистрация и вход

- Экран логина: ввод пароля, кнопка "Войти"
- Биометрический вход (отпечаток/лицо) — **только Android**
- Регистрация: никнейм + пароль (без телефона/почты) → генерация ключей
- Импорт бэкапа прямо с экрана регистрации (альтернатива обычной регистрации)
- Переключение языка RU/EN в правом верхнем углу
- Ошибка при несовпадении паролей / коротком пароле / уже занятом имени
- ~~Замаскированный экран-калькулятор~~ — **скрыто из публичной сборки**: переключатель убран из `WipeSettingsScreen` (был сделан под конкретную несостоявшуюся кастомную интеграцию, разблокировка была зашита как фиксированный пример "4+20=24", не настраивалась пользователем — не годится как реальная защита для общедоступного приложения). Код (`CalculatorScreen.kt`, механизм подмены иконки через `PackageManager`) оставлен в репозитории на будущее, но проверять в текущей сборке нечего — экран недостижим.

## 2. Контакты

- Список чатов (главный экран): сортировка по последнему сообщению, непрочитанные, статус подключения
- Добавление контакта через инвайт-код (обмен кодами, оба должны добавить друг друга)
- Инвайт-код: показывается как QR и текст, копируется в буфер
- Long-press / правый клик по контакту → меню (мьют, блок, удалить и т.д. — стоит пройтись по каждому пункту меню)
- Открытие профиля контакта
- **Автоматическое установление анонимного канала** (новое): сразу после добавления контакта по инвайт-коду приложение само, невидимо для пользователя, пытается обменяться анонимными токенами через mailbox — не дожидаясь, пока пользователь напишет первое сообщение. Пока обмен не завершён, при открытии чата с этим контактом должен показываться индикатор "Устанавливаем защищённый канал..." вместо поля ввода, отправка заблокирована (текст, фото, файл, голос — все каналы). Как только обмен токенами завершится (у обеих сторон — двусторонний), индикатор должен исчезнуть без выхода из экрана чата, поле ввода — открыться. Если один из собеседников в момент добавления контакта не в сети — повтор попытки должен идти автоматически (30/60/90 сек, затем каждые 90 сек), а также сразу при открытии чата с ещё не готовым контактом.

## 3. Переписка один на один

- Отправка текста, доставка/прочтение статуса, индикатор "печатает"
- Реакции на сообщение: **свайп влево** по сообщению открывает меню реакций (не удаление!)
- Ответ на сообщение (quote/reply): **свайп вправо** (60+ dp) по сообщению
- Редактирование сообщения (long-press / правый клик → редактировать)
- Удаление сообщения (через меню, не свайпом)
- Копирование текста сообщения
- Отправка изображения (сжатие, чанками), полноэкранный просмотр, сохранение в галерею
- Отправка файла (чанками), сохранение
- Голосовые сообщения: запись (удержание на Android / клик на Desktop), прослушивание
- Видео (**Android**): запись и отправка через камеру
- **Отправка геолокации**: значок 📍, координаты отображаются на карте (osmdroid) — реальная фича, не выдумка
- Аудио/видеозвонок из чата (значок звонка)
- Проверка ключа собеседника (см. раздел 10)

## 4. Группы

- Создание группы: имя, аватар/эмодзи, выбор участников — **Android**
- Отправка сообщений в группу, реакции, редактирование, удаление
- Список участников с бейджами админа
- Админ: добавить участника, повысить до админа, удалить участника
- Любой участник: покинуть группу
- Создатель: удалить группу целиком
- **Ротация группового ключа при удалении участника** — этот механизм в этой же сессии чинился (баг, при котором новый ключ уходил самому удалённому участнику), стоит проверить особенно внимательно: удалённый участник НЕ должен расшифровывать сообщения после своего удаления

## 5. Каналы

- **Полностью отключены на уровне UI на обеих платформах.** Код и таблицы БД остались, но создать/подписаться/посмотреть канал через интерфейс нельзя. Проверять не нужно — тестировать нечего, экран недостижим из навигации.

## 6. Звонки

- Входящий звонок: экран с приёмом/отклонением, авто-отклонение по таймауту
- Активный звонок: мьют микрофона, вкл/выкл камеры, переключение фронт/тыл камеры (**Android**), громкая связь/наушник (**Android**), завершение
- Групповые звонки на несколько участников — **только Android** (на Desktop поддержки нет, только 1:1)
- Датчик приближения (экран гаснет у уха) — **только Android**

## 7. Резервное копирование

- Экспорт: пароль бэкапа → выбор места сохранения → зашифрованный файл (AES-256-GCM, PBKDF2 100k итераций)
- Импорт: выбор файла → ввод пароля → восстановление контактов, сообщений, групп, ключей
- Проверить: после импорта видна вся история, групповые сообщения расшифровываются (значит, групповые ключи тоже восстановились)
- Ошибка при неверном пароле бэкапа

## 8. Безопасность и экстренные меры

- **Панич-пароль**: отдельный пароль, при вводе вместо обычного — мгновенное необратимое уничтожение данных
- **Уровни уничтожения**: SOFT (только сессии/кэш), HARD (все ключи/файлы/БД, опционально создание decoy-аккаунта), NUCLEAR (HARD + системный атомарный wipe)
- **Волшебная кнопка громкости**: 5 быстрых нажатий "вниз" за 3 секунды запускают экстренное уничтожение (проверено в коде, реально существует)
- **Decoy-режим**: после панич-пароля или волшебной кнопки показывается поддельный список чатов с сгенерированными сообщениями — ничего реального там нет, всё бутафория
- **Dead Man's Switch**: включить, задать интервал, кнопка "отметиться" (check-in), предупреждение при истечении, автоуничтожение после grace-периода
- **Автовайп по таймауту бездействия**: включить, задать часы
- **Реакция на обнаружение угрозы**: авто-wipe или скрытный (stealth) режим при срабатывании
- **Paranoid Mode**: включение через подтверждение, подавление логов, сканирование угроз при каждом возврате в приложение (прокси, пользовательские CA-сертификаты, VPN, ADB, режим разработчика), опциональная отправка алерта на свой URL
- **Диагностика безопасности**: запуск полного набора самопроверок (постквантовый ML-KEM, детекция отладчика/root, проверка подписи приложения и т.д.) с прогрессом и результатами

## 9. Проверка ключей (verify key)

- Экран показывает публичный ключ контакта тремя способами: QR-код, эмодзи-представление, hex-отпечаток
- Отметка "проверено" после сверки (лично или по звонку)

## 10. Настройки / профиль

- Никнейм, ID (fingerprint), инвайт-код
- Тема оформления: **3 варианта** (Navy, Dark, Light — не больше, несмотря на то что можно было предположить иначе)
- Автоблокировка приложения по неактивности: **3 варианта — 5 / 15 / 30 минут** (не 0/1 час, таких вариантов нет)
- Показывать/скрывать текст сообщения в уведомлениях
- Установка / смена панич-пароля
- Переходы: Серверы, Бэкап, Диагностика безопасности, Настройки уничтожения

## 11. Серверы и сеть

- Список серверов: добавить/удалить, включить/выключить
- Режим "фиксированный сервер" vs "авто" (федерация — при обрыве связи клиент сам переключается на резервный сервер по списку известных, включая обнаруженные через федерацию)
- **Cover traffic (маскировочный трафик)**: три режима — OFF / MODERATE (пустой пакет раз в 5 сек) / AGGRESSIVE (раз в 1 сек)
- Tor: на Android — через Orbot (системный VPN, прозрачно); на Desktop — обнаружение локального SOCKS5-прокси, работает для `.onion`-адресов
- Индикатор подключения (какой сервер, статус)

## 12. Уведомления

- Уведомление о новом сообщении (с превью текста или без — по настройке)
- Уведомление о групповом сообщении
- Уведомление о звонке (принять/отклонить прямо из шторки)
- Предупреждение Dead Man's Switch о скором автовайпе

| Что | Android | Desktop |

## Известные ограничения (не баг, так и задумано)

- Поиск по сообщениям — не реализован
- Запись звонков — намеренно отсутствует (приватность)
- Каналы — отключены полностью на уровне UI на обеих платформах
- История звонков как отдельный лог — не хранится (только сигналинг, эфемерно)

## Что стоит проверить особенно внимательно (свежие изменения этой сессии)

Эти вещи чинились/менялись за последние несколько дней — им нужно больше внимания, чем остальному:

1. **Ротация группового ключа при удалении участника** (раздел 4) — только что найденный и исправленный баг, критично проверить, что удалённый участник не читает новые сообщения
2. **Постквантовая гибридная защита (ML-KEM-768)** — новая крипто-схема, стоит прогнать полный цикл: регистрация → добавление контакта → первое сообщение → обычная переписка на обоих платформах
3. **Анонимный batch-фетч prekey-бандла** — при первом сообщении новому контакту должен уходить пакет с "приманками", а не прямой запрос
4. **Идентификация на сервере** (register vs handshake) — сложно проверить руками без второго клиента с чужим ключом, но стоит хотя бы убедиться, что обычная регистрация/вход по-прежнему работает без ошибок после фикса
5. **Rate-limiting на сервере** — тоже сложно проверить вручную одному, но стоит убедиться, что обычная нагрузка (быстрая переписка, создание канала — если понадобится, создание нескольких серверов в списке) не начинает внезапно блокироваться
